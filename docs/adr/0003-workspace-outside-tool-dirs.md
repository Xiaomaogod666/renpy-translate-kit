# 工作区放在两个工具目录之外

原实现把工作区放在 `renpy_translate_kit` 内部（`kit.json` 里 `"workspace": "workspace"`）。
导出文件、翻译进度、还原与关钩子的备份全都埋在工具目录里：

- 用户找不到刚导出的待翻译文件，得顺着工具内部目录一层层点进去；
- 工具目录本身是可整体替换的（升级或换一份 `renpy_translate_kit` 即可），
  用户数据放在里面会被连带丢掉，或者每次升级都得先手工把 workspace 抢救出来。

## 考虑过的其它做法

- **保持原样，只在文档里写清楚位置**：治标不治本，升级丢数据的问题还在。
- **放到用户的“文档”目录**：与"整个文件夹搬走/拷走就能用"的绿色版定位冲突，
  且换电脑时工具与数据分居两处。
- **放到游戏目录里**：污染游戏目录，与"游戏目录只接受工具自身的改动"这一既有原则冲突，
  去掉汉化和关钩子时还要多清理一处。
- **放到两个工具目录的上一级（采用）**：`workspace` 与 `renpy_translate_kit`、
  `projz_renpy_translation` 平级，既在工具包内（整个文件夹搬走仍能用），
  又不在任何会被替换的目录内部。

## 后果

- `kit.json` 的 `workspace` 改为 `../workspace`，仍相对 kit 目录解析；
  想放到任意位置把它设成绝对路径即可。
- 老布局的 workspace 需要一次性搬移（随本次改动完成）。
- 导出完成时打印的路径本身就是新位置，用户可直接去那里找文件。
