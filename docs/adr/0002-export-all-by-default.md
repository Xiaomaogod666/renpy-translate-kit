# 默认导出全部未翻译文本，而不是每批 300 行

原实现把每次导出截到 300 行（`batch_size`），理由是"怕一次给对话太多、翻不动"。
但实际使用中这个上限没有解决问题，反而制造了问题：

- 用户的诉求是"有多少文本导出多少"，把整份文件一次交给对话本来就是他的选择；
  引擎生成的翻译文件要完整覆盖才有意义，人为切成几十批反而让进度难以核对。
- 一批翻不完时，剩下的行要等下一次拖入才会重新出现；
  导出与回填之间的状态越碎，"哪批翻了、哪批没翻"越难说清。
- 300 行是随手取的一个数，没有任何来自游戏文本分布的依据。

因此默认不带行数上限：省略工具本体的 `--limit`，一次导出那一刻全部未翻译的行。

## 考虑过的其它做法

- **保留 300 行，只是改成更可配**：仍是默认切批，用户还得先学会改配置。
- **默认全量，但按文件大小自动切批**（比如每 5000 行一个文件）：避免了单文件过大，
  但把"切在哪"变成新的隐式规则，且回填要拖多个文件。工具本体支持单文件，就不必加这层。
- **默认全量，配置里留一个逃生阀**：采用了。想先小批量试翻质量的人可以
  把 `export_limit` 设成 300，行为与旧版一致。

## 后果

- 大游戏首次导出的 JSON 可能几 MB（实测约 9800 行 / 600 KB），
  直接丢给对话时要留意上下文长度；需要时用 `export_limit` 分批。
- 上限"至少 2 行"的约束来自工具本体（`command/file/base.py:99` 对 `--limit` 的断言），
  所以 `export_limit` 只接受 0（全部）或 2 以上的值；1 与非法值一律退回全量。
- 导出文件名仍带递增序号（`..._002.json`），manifest 里的 `batch` 继续递增；
  序号只用于区分文件，不再意味着"每份都只有 300 行"。
