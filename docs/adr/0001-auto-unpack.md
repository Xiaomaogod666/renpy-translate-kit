# 自动解包游戏，而不是要求用户先用 UnRen 手动解包

工具本体 (projz_renpy_translation) 完全不做解包，README 只是告诉用户"先用 UnRen 解包"。
但用户的诉求是"把游戏目录拖进去就完事"，不接受在看文档学一个额外工具、按固定按键序列操作。

因此这一层外壳自己带解包器：`vendor/unrpa`（解 `.rpa`）与 `vendor/unren`（把 `.rpyc` 反编译回 `.rpy`），
在拖入游戏时先判断是不是压缩包状态，是就自动解开再继续。

## 考虑过的其它做法

- **保持工具本体的做法**：报错并给出 UnRen 的下载地址与按键步骤。无额外代码、无第三方依赖，
  但用户每次拿到一个新游戏都要手动操作一遍。
- **只在检测到未解包时提示、由用户确认后再解**：自动化程度低一档，但少一次自动写入游戏目录。

## 后果

- 首次处理一个游戏会多花时间，且会对游戏目录产生写入（新增 `.rpy`）。
- 解包只补游戏目录里缺失的脚本文件，不覆盖已有文件、不导出图片音频
  （RenPy 能直接读 `.rpa` 里的资源，只有文本需要落成 `.rpy` 才扫得到）。
  这一点直接关系到"重复拖入不会覆盖已生成的译文"。
- 引入了两个第三方组件的许可与维护负担：unrpa 为 GPL-3.0，unrpyc 为 MIT。
- 解包失败（加密包、过老或混淆的 RenPy）时仍回退到手动 UnRen 的指引。
