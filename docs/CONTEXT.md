# CONTEXT

术语表。只记录领域词汇的含义,不含实现细节。

## 拖拽工具包 (translate kit)
围绕 projz_renpy_translation 的一层简化外壳:用户把游戏目录拖到入口文件上即完成导出/回填,不需要手工敲命令。

## 导出 (export)
把某游戏某语言的**未翻译行**以 tid→原文 的形式写成一个待翻译文件,交给外部翻译手段(AI 对话、Google 文档翻译等)。
- 已翻译的行不会被再次导出,因此"导出 → 翻译 → 回填"可以反复进行,每次取的都是当时尚未翻译的部分。

## 导出批次 (export batch)
一次导出所取的那批未翻译行。默认**不设行数上限**,即导出那一刻全部未翻译的行;
需要小批量试翻时可在配置里设 `export_limit` 限行。
每次导出取的都是"那一刻仍未翻译的行",所以上一次没翻完的行会原样出现在下一次导出里,
不会有行被跳过或漏掉。

## 回填 (apply back)
把翻译好并返回的待翻译文件按 tid 导入索引,并让译文在游戏中生效。
- 只接受与原文不同的行;译文为空或多个译文对应同一 tid 时按工具既有规则丢弃。

## 回填文件
已填入译文的待翻译文件,格式不变(键仍是翻译标识)。它与待翻译文件是同一个文件在不同阶段的叫法。

## 待翻译文件 (batch file)
导出产物。格式为 JSON,键是翻译标识 (tid),值是原文。文件名中带游戏名与语言,用于回填时定位所属游戏。

## 工作区 (workspace)
每个游戏一个子目录,集中存放该游戏的待翻译文件、回填文件与翻译进度信息。游戏目录本身只接受工具自身的改动。
- 默认放在**两个工具目录的上一级**(`<父目录>\workspace\`),与工具目录平级而非藏在 kit 目录内部:
  升级或替换工具目录不会连带用户的翻译进度与备份,用户也能直接找到导出文件。
- 位置由 `kit.json` 的 `workspace`(相对 kit 目录解析)决定,可改成任意路径。

## 翻译标识 (tid / TranslationIndex id)
工具内部对每行文本的稳定编号,是导出与回填配对的唯一依据。外部翻译手段必须原样保留,不得改动、重排或省略。

## 索引 (TranslationIndex)
工具对"某个游戏 + 某个语言"的翻译数据库记录,带别名(nickname)与标签(tag)。别名用于在命令中指定它。

## 应用到游戏 (deploy)
回填之后把索引内容生成为游戏可加载的翻译文件 (`game/tl/{语言}/*.rpy`),使游戏内可切换到该语言。

## I18N 插件
工具往游戏注入的语言/字体切换插件。用途:让游戏内能选中新语言,并用带中日韩字形的字体正确显示译文。默认字体不含 CJK 字形,缺少它时中文可能显示为方块。

## 入口文件
供拖拽的批处理文件。把游戏目录拖进去表示"导出全部未翻译文本";把回填文件拖进去表示"把这份译文装回游戏"。
一个文件同时承担导出与回填两种入口,靠拖入的对象是目录还是文件来区分。

## 注入 (injection)
工具把自己的代码文件写进游戏目录,让游戏在启动时能向工具报告文本清单。这是工具能读到文本的前提,
因此第一次导出必然要改一次游戏目录、并启动游戏一次(启动后会自动退出)。
之后可选地再注入 I18N 插件。注入是可撤销的:工具记录注入状态,支持撤销。

## 目标语言
译文要落到的语言。默认简体中文,可在配置里更换;换语言相当于在该游戏上开一条独立的翻译线。

## 还原 (untranslate)
把工具装进游戏的东西全部撤掉,让游戏回到未经翻译的状态:删掉自己生成的译文文件与注入的支持脚本,
把被改过的游戏脚本还原,清掉运行时缓存。
- 只撤自己的产物。游戏自带的其他语言包、存档、原作者脚本一律不动。
- 撤之前先整体备份到工作区,可原样盖回。
- 判定"某个译文文件是不是自己写的"只能看明文脚本里的来源标记(编译产物里没有注释)。
- 撒掉支持脚本后,索引里记录的注入状态要一并复位,否则下次翻译会卡在"要求先注入"这一步;
  因此翻译代号启动时会检查并自动补回。

## 翻译场所
翻译动作发生在工具之外——把待翻译文件交给 AI 对话或翻译网站,工具只负责给出文件和收回文件。

## 翻译提示词 (translation prompt)
交给对话 agent 的翻译说明,与待翻译文件一起发出。要求 agent 先产出《翻译任务书》(作品档案/人物表/术语表/体例约定/分批计划/风险清单)再动笔,
并规定了变量与标签原样保留、按语境而非逐词翻译、短应答按语气区分、跨批术语一致等要求。
分四段: 通用提示词、任务书模板(空表)、侦察配方(一段可直接跑的统计与正则代码)、交付前自检。
- 刻意做成**游戏通用**: 人物表、术语表、文体判断都不预填,由 agent 自己从待翻译文件里推出来
  (词频找专名、重复句找口头禅、行尾空格与破折号找被切开的句子);换游戏时全部重来,不沿用上一个游戏的知识。
- 与本机装的五个翻译技能配合(见下节)。提示词要求 agent 开工前先看一眼技能库,读不到也能自足执行。
- 第三节「怎么翻」的第 7 条是**翻译腔清单**:冠词不落地、连接词能省就省、从句别名词化、
  判断句别倒装、被动少用被、的字不叠加、书面词换口语词、短应答按情绪换词。
  这些不是凭空写的,来自对真实译文 `_t_*.json` 的统计(见 `docs/翻译腔对照示例.md`)。

## 翻译技能 (translation skill)
装在 ZCode 用户技能目录 `~/.zcode/skills/` 下、供对话 agent 调用的翻译方法论,与工具本身解耦
(工具只产出/收回 JSON,技能只在翻译环节起作用)。分两批装,共五个:
- `en-zh-translation-polish` (MIT, HoraceLuBFA): 英译汉润色,七阶段流程(文本分析定归化档位 →
  理解脱壳 → 意合优先初译 → 润色诊断 → 音韵节奏 → 准确性质检 → 标点归一),
  参考文件三份: 技法、翻译腔病症九类、文本分析与 QA。**第三批增补**两份身体/性描写语域参考
  (`literary-fiction-sexual-register.md` 临床↔口语切换随原文走、`libertine-vocabulary.md` 直译词汇表),
  取自 MIT 的 `3060226349kk-cmd/en-zh-max`(与前者同源,三份参考表 md5 相同)。
- `renpy-translation` (MIT, Waiyakorn1879/for-the-plot): Ren'Py 游戏本地化管线,
  角色语域模型(自称/对称/禁用词/关系映射)、token 多重集校验、翻译记忆、断点续跑。
  **第三批增补**两处引擎知识: `translate_string()` 存在时译文必须进 `translate <lang> strings:` 节
  (进 dialogue 块会静默不生效), 以及反转文本标签 `{b}`→`{/b}` 的成因与栈式修复。
- `translate-visual-novel` (MIT, 9029kazuki/codex-visual-novel-translation): 视觉小说全流程本地化,
  11 步管线(提取→证明无损往返→术语与角色声音→校准场景冻结 Bible→派工→独立审校→回填→试玩→打包)。
  核心资产是**译文合同**: 五级优先级(剧情事实 > 说话人指代 > 人设语域 > 目标语节奏 > 原文语序)、
  结构不变量、以及「不确定要写进 issues,不许藏进流畅译文里的猜测」。
- `translate-polisher` (MIT, rookie-ricardo/erduo-skills): 精翻四步法(分析→初译→审校→终稿),
  风格/读者预设、长文分块与接缝检查、长句短句节奏规矩(修辞性独立短句必须保留独立成句)。
- `humanizer-zh` (MIT, op7418/Humanizer-zh, 18.6k★): 中文去模板化检查表,31 条模式分 A–F 组。
  F 组是中文特有的翻译腔痕迹(「的」字层叠、「进行＋动词」、被字句堆叠、四字词排比、套话收尾),
  正对本 kit 的机翻味问题。附 `tests/check_structure.py`。
- 装法是手工放目录(GitHub tarball 解包后复制,逐文件 md5 校验),不改 frontmatter 的 name/description;
  只给缺 `when_to_use` 的那个补了一行触发语。
- 装的是**方法论**,不是自动流水线:仍需把待翻译 JSON 交给对话,只是对话这次有了专门的作业指导。
- 新装/改过的技能**要新开一次对话**才会被扫描到(`/` 菜单与自动触发都在会话启动时发现)。

## 译文自检 (translation check)
回填之前对"译文与原文"做的一次比对,预判哪些行会让游戏对不上号。
- **错误**: 编号缺失/多出、值不是文本、变量丢失或凭空出现、标签不一致、字面换行丢失、格式串被改。
- **提示**: 与原文相同(等于没翻)、译文为空、整句仍是英文、长度越界、半角引号、首尾空格不一致。
- 尺子按已确认的好译文校准: 变量只比名字集合不比出现次数(中文复述主语会把 `[pf]` 从 1 次变 2 次),
  长度阈值放到 1.4 倍 + 6 宽; 版权行、装饰符号、纯符号条目的"与原文相同"不算漏翻。
- 它只预判,不做决定: 真正丢弃漏翻行的是回填环节本身(与原文相同的行不进索引)。

## 汉化钩子 (third-party hook)
某些第三方汉化包在打包游戏时塞进剧本的一段注入(伪装成 `init python` + 一行 `exec(base64.b64decode(...))`)。
它在游戏启动时解密并释放一个随机名字的 `.bin`(实为 PE DLL)到存档目录,再调用它把界面文字送去在线翻译服务,
同时注册一个推广弹窗。特征: 字符串全部藏在自定义的异或函数里、靠 `config.replace_text` 挂到引擎渲染链上。
与两个载体文件(`game/audio/dl_failed.mp3` 里加密着这个 DLL、`dl_success.mp3` 用作校验样本)配套。
判定它必须先把异或还原出来再比对特征串;`.rpyc` 里只看得到 base64 字面量,所以只能查明文 `.rpy`.

## 关钩子 (unhook)
精确删掉注入的那两行(其余一字不改),连编译产物、运行时缓存、已释放的 `.bin` 一并删除,动手前整体备份。
- 与"还原"的区别: 还原撤的是**本工具包**装进去的东西,关钩子撤的是**第三方汉化包**塞进去的东西,两者互不影响、可分别执行。
- 注入只占两行,删掉后 `characters.rpy` 的其余内容(以及它自己的 `init python` 块)原样保留。
- 换行风格必须原样保留(真实包是 CRLF),按字节读写,不能走文本模式。

## 解包 (unpack)
把游戏的压缩包 (`.rpa`) 与已编译脚本 (`.rpyc`) 还原成工具能读的明文脚本 (`.rpy`)。
未解包的游戏,工具读不到文本,所以这是翻译的前置条件。
